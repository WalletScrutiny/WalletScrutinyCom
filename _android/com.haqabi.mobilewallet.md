## App Description

Haqabi Wallet is a multi-chain cryptocurrency wallet application supporting Bitcoin, Ethereum, HAQQ (ISLM), Tron, BNB Chain, Cosmos, Solana, and other digital assets. The application integrates cryptocurrency swap functionality and fiat on-ramp services for purchasing digital assets with local currency. The wallet markets itself as non-custodial with private keys stored encrypted on the user's device using AES algorithms, and includes a "seedless recovery" feature that allows wallet restoration without traditional seed phrases.

## Analysis

The application claims to be a "Secure Non-Custodial Crypto Wallet" where users *"maintain complete control over your crypto assets"* and "no one can freeze your funds." 

However, the wallet employs a proprietary **"seedless recovery"** mechanism that uses distributed key storage, dividing the private key into three parts where users need two out of three parts to restore wallet access. 

The critical question is the location and control of the third key part—if Haqabi or a third party holds this component, it introduces a custodial element despite non-custodial claims.

[No source code](https://github.com/search?q=%22com.haqabi.mobilewallet%22&type=code) repository was found in searches for "Haqabi Wallet github" or "Haqabi Wallet source code" or "com.haqabi.mobilewallet." 

While the related HAQQ Network has open-source repositories, Haqabi Wallet appears to be developed as a closed-source application by Haqqex Ltd. Technical documentation provides minimal details about the implementation of the distributed key system, using vague terms like "smart algorithms" without cryptographic specifics. Without access to source code, the security model, key management implementation, and true custody nature of the distributed recovery system cannot be independently verified or audited.

**We tested the app:** [Testing documentation](https://x.com/BitcoinWalletz/status/1990681913871438151) shows the 12-word seed phrase provided by Haqabi fails to import into Electrum Desktop using standard BIP39 derivation paths (p2pkh, p2wpkh-p2sh, p2wpkh). The wallet address generated by Haqabi (`bc1qdt80cpl7u55tswdk88npd03v9l0g4e9uen33vv`) does not match any of the addresses generated in Electrum from the same seed phrase. 

This proprietary implementation creates vendor lock-in, preventing users from independently accessing their funds with standard wallet software.

The verdict is **custodial**.
